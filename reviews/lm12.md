## Findings in full

### 1 (major, independent reviewer)

- **Where:** §3 'The index identity', line 161: "Three things break the identity: weights that drift every day with relative prices, members or share counts that change, and members outside the 28 sectors."
- **Problem:** The identity derived just above it (line 157) already has daily weights w_{i,t-1}, so drifting weights do not break it. Drift only defeats a fit with constant coefficients. The sentence contradicts the derivation and overview bullet 2 ("an accounting identity with drifting weights", line 19), and it blurs the section's main point.
- **Correction:** "Three things keep a fit with constant coefficients from reproducing the identity: the weights drift every day with relative prices, members or share counts change, and some members lie outside the 28 sectors." Then drop or merge the next-but-one sentence, "A fit with constant coefficients can only approximate the identity."
- **Evidence:** Line 157 gives 1+y_t = Σ_i w_{i,t-1}(1+R_{i,t}) with w set at each previous close. Line 19 calls it an identity "with drifting weights".

### 2 (major, independent reviewer)

- **Where:** Case (line 33), notation note (line 59), §3 lines 159–161 ("The book has no weight file to check them"), Summary line 533 ("TAIEX on its 28 sectors")
- **Problem:** IndexS03, which the module itself cites (2023.06 revision, 附表一), lists four more industry indices with base date 2023-06-30: 綠能環保類, 數位雲端類, 運動休閒類 and 居家生活類. These are leaf indices (§三(四): each holds the companies of one industry), and none is among the book's 30 series (data/raw/sectors/ has 403 files = 31 series × 13 windows). So from July 2023 some TAIEX members certainly lie outside U28. That period covers the whole last-250 case window, the 2024–2026 yearly fits and part of 2023. The module treats this third break as uncheckable and calls U28 TAIEX's own sectors. TWSE also publishes the aggregates 水泥窯製類, 塑膠化工類 and 機電類, so the brief's "every TWSE sector index except the aggregates" (plans/vol-2.md) is also wrong.
- **Correction:** In §3, replace "The book has no weight file to check them" with a sentence along these lines: "Since 30 June 2023 TWSE has also published four more sector indices (綠能環保類, 數位雲端類, 運動休閒類, 居家生活類; IndexS03, Appendix 1) that are not among the 30 series used here, so from July 2023 (the whole last-250 window) some TAIEX members lie outside U28." In the Summary, write "TAIEX on the 28 sector indices of U28". Check FinMind's index listing for these four ids: I could not, under the no-API rule. If FinMind serves them, correct "FinMind serves daily closes of 30 TWSE sector indices". Keep the 0.990 sum unexplained, as the brief requires.
- **Evidence:** pdftotext of IndexS03.pdf (2023.06 修訂), 附表一: the four indices with base 2023-06-30; 附表二 lists them among the 35 indices. IndexS02.pdf (2023.04): TAIEX = 總發行市值 ÷ 當日基值 × 100. Last-250 window 2025-09-25 → 2026-10-08.

### 3 (minor, independent reviewer)

- **Where:** §4 'Conditioning', line 262: "A call on X̃ therefore faces κ(X̃), not its square."
- **Problem:** Working on X̃ avoids forming X̃ᵀX̃, but the sensitivity of a least-squares problem is of order κ + κ²·tanθ for any backward-stable solver, where θ is the angle between ỹ and the fit. On this module's data the κ² term is not negligible. U28 full sample: tanθ = 0.130, so κ²tanθ = 14.1 against κ = 10.40. U28 + Electronic 2016: tanθ = 0.0061, so κ²tanθ ≈ 2,530 against κ = 642. The worst case is not realized here: lstsq's relative error for the 2016 row is 8.6e-16 against a 60-digit reference, and the normal equations' is 9.0e-12. So the exhibit's conclusion stands.
- **Correction:** "A call on X̃ therefore never squares κ(X̃) by forming X̃ᵀX̃; when the residual is small, its accuracy depends on κ(X̃) rather than κ(X̃)²."
- **Evidence:** Own script with mpmath at 60 digits on the exact float inputs; tanθ = ‖ε̂‖/‖X̃β̂‖.

### 5 (minor, independent reviewer)

- **Where:** (12.7) line 302 and Glossary "M⁺=VS⁺Uᵀ"; code comments line 367 "Vh=V'" and line 507 "L'"
- **Problem:** §4 defines the matrix form USVᵀ only when rank M = N (every s_k > 0), and u_k only for s_k > 0. So "VS⁺Uᵀ, where S⁺ … keeps the zeros" is undefined in the module's own terms for the rank-deficient design it serves (22×29, rank 22). `np.linalg.svd(design, full_matrices=False)` returns U 22×22, s (22,) and Vh 22×29 (checked), so Vh is not V transposed. - **Correction:** Define M⁺ := Σ_{s_k>0} v_k u_kᵀ/s_k, "that is VS⁻¹Uᵀ with U, S, V restricted to the r = rank M positive singular values". Comments: "# s descending; the rows of Vh are the v_k" and "# returns the upper factor, L transposed".
